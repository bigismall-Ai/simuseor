## 1. 术语

| 词 | 定义 |
|---|---|
| **源（source）** | 一个对外数据源，对应 `backend/app/sources/` 下的一个适配器 |
| **通路（path）** | 一个源的一次尝试路径：`direct`（直连）/ `proxy`（经全局代理）/ `mirror`（该源自带的镜像或加速前缀） |
| **当前生效通路** | 该源按设置实际会走的路径（`proxy_enabled` 决定走代理还是直连；`use_mirror` 决定走镜像） |
| **探针（probe）** | 一次小请求，判定某源某通路是否可达；只读、不落业务数据 |
| **探针结论（verdict）** | 某源的综合结论：`ok` / `degraded` / `down` / `unknown` |
| **门控（gating）** | 用探针结论决定某个源在发现页 / 下载页**是否作为可选入口出现** |

## 2. 探针语义

### 2.1 探测目标（每源探什么）

探针只打**小请求**：响应体读取上限 64 KB，不落盘、不进缓存目录、不下载权重。

| 源 | 目标 URL | 方法 | 为什么选它 | 对应实现 |
|---|---|---|---|---|
| huggingface | `https://huggingface.co/api/models?limit=1` | GET | 与搜索同端点，能同时验 DNS/TLS/线路 | `sources/huggingface.py:143` |
| huggingface（镜像） | `{settings.sources.huggingface.mirror}/api/models?limit=1` | GET | 仅当 `use_mirror=true` 才探；默认镜像 `https://hf-mirror.com` | `sources/huggingface.py:84`、`config.py:84` |
| modelscope | `https://modelscope.cn/openapi/v1/models?PageSize=1` | GET | 与搜索同端点 | `sources/modelscope.py:100` |
| civitai | `https://civitai.red/api/v1/models?limit=1` | GET | **API 底座是 civitai.red，不是 civitai.com** | `sources/civitai.py:19,123` |
| civitai（网页侧） | `https://civitai.com`（或 `civitai.red`） | HEAD | 网页侧与 API 侧线路可能不同；完整目录开关决定用哪个域名 | `sources/civitai.py:81` |
| github | `https://api.github.com/rate_limit` | GET | 免鉴权、**不消耗**未认证的 60 次/小时配额 | `sources/github.py:16,42` |
| github（raw 域） | `https://raw.githubusercontent.com/Comfy-Org/ComfyUI-Manager/main/README.md` | HEAD | 节点清单与模板都走 raw 域；只探线路，**不拉** 几 MB 的 custom-node-list.json | `nodes.py:45-46` |
| templates | `https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/README.md` | HEAD | 模板源无目录索引，用仓库 README 的 HEAD 验 raw 域线路 | `sources/comfytemplates.py:15` |
| comfyhub | `https://comfy.org/workflows/download` | HEAD | 免鉴权固定源 | `sources/comfyhub.py:19` |
| demo | **不探** | — | 本地假数据，URL 是 `example.invalid`，恒可用 | `sources/demo.py:72` |

> **纪律**：探针不得访问业务接口做「顺便验证」（如 HF 的 repo tree、GitHub 的业务 API），
> 那会消耗配额并可能触发限流。GitHub 一律用 `/rate_limit`。
>
> 第三轮起每条通路还要**测速**（延迟 + 吞吐），测速目标与口径见 **§2.5**。

### 2.2 判定阈值

| 项 | 取值 | 理由 |
|---|---|---|
| 单请求超时（直连） | **5 s** | 墙内直连失败的典型表象是「握手后无响应」，5 s 足以判定并快速翻案 |
| 单请求超时（代理） | **8 s** | 代理多一跳、首连要握手，放宽 3 s |
| 重试 | 最多 **1 次**（共 2 次尝试），间隔 **400 ms** | 只对「超时 / 连接错误 / 5xx」重试；4xx 不重试（重试也不会变） |
| 成功判据 | HTTP **< 400** 且响应体读取 ≤ 64 KB | 3xx 跟随重定向后判最终码 |
| 429 / 401 / 403 | 判 **「可达但受限」** → `degraded`，**不是** `down` | 对端活着，只是要令牌或被限流 |
| 5xx | 重试一次仍 5xx → `down`（对端异常） | |
| 单源总耗时上限 | **12 s**（两条通路并发，各自有超时） | |
| 全局并发 | **6**（源内 2 条通路并发） | 与封面批量 16 路（`routes.py:1013`）不同，探针要更克制 |
| 一轮整体上限 | **15 s** | 超过则未完成的源记 `unknown`（本轮不判死） |
| 响应体 | 只读头 + 限流读，不整包下载 | |

### 2.3 失败原因分类与展示措辞

界面只给**一句人话 + 一个可执行动作**，分类明细进日志与规格。

| 类别 | 触发条件 | 界面措辞 | 建议动作 |
|---|---|---|---|
| `dns` | 域名解析失败 | 域名解析失败：civitai.red | 检查 DNS / 代理地址 |
| `timeout` | 超过单请求超时 | 直连超时（5 秒无响应） | 试代理或镜像 |
| `tls` | 证书链校验失败 | TLS 握手失败：证书校验未通过 | 检查系统时间 / 证书 |
| `refused` | 连接被拒 | 连接被拒绝：目标端口未开放 | 检查代理是否在运行 |
| `blocked` | 直连超时 **且** 代理同址成功 | 直连被阻断，代理通路可用 | 一键改走代理 |
| `rate_limited` | HTTP 429 | 可达但被限流（HTTP 429） | 填 Access Token / 稍后再试 |
| `forbidden` | HTTP 401 / 403 | 可达但需要授权（HTTP 403） | 填 Access Token |
| `server` | HTTP 5xx | 对端服务异常（HTTP 502） | 稍后重试 |
| `unknown` | 其它异常 | 未知错误：<异常摘要 120 字> | 重新探测 |

> `blocked` 是最有价值的一类：它直接告诉用户「不是源没了，是这条路被挡了，换条路就行」。

### 2.4 缓存与失效

| 项 | 取值 |
|---|---|
| 缓存实现 | 复用 `backend/app/cache.py` 的 `TtlCache` 模式（进程内，不落盘） |
| 缓存键 | `{source}#{path}#{target_host}#{proxy_fp}#{cfg_fp}`；`proxy_fp` = 代理 host:port 摘要，`cfg_fp` = 该源 proxy_enabled / use_mirror / mirror 摘要 |
| TTL（`ok`） | **15 分钟** |
| TTL（`down`） | **3 分钟**（坏消息要更快翻案） |
| TTL（`degraded` / 受限） | **10 分钟** |
| 命中过期缓存 | 先返回旧结论并标 **stale**，同时后台刷新；同一键 **single-flight**，不并发重复探 |
| 立即失效时机 | ① 改代理 host/port ② 改某源 proxy_enabled / use_mirror / mirror ③ 点「重新探测」 ④ 后端启动后首次访问触发一次后台刷新 ⑤ 点「恢复默认」后 |
| 冷却 | 手动重探 10 秒内不重复触发（防假忙碌） |
| 落盘 | **不落盘**。重启后重新探一次是刻意的：重启后旧结论更不准 |

> 探针结论**不写进 settings.json**。settings.json 是配置，不是状态；状态放内存缓存。

### 2.5 测速口径（第三轮新增）

用户要求把探针从「能不能连」升级成「**能不能连 + 有多快**」。
**四态结论不变，但每一态都要带上速度读数**（延迟 ms ＋ 吞吐 MB/s），用户才能直接比哪条路更快。

#### 2.5.1 测哪几条通路

| 通路 | 什么时候测 | 测什么 |
|---|---|---|
| `direct` 直连 | 总是测 | 官方地址直连 |
| `mirror` 镜像 | **该站配置了镜像才测** | HF 的 hf-mirror、GH 的加速前缀；没配镜像就不测这一条（界面标「未配置」） |
| `proxy` 代理 | **全局代理已配置、且该站允许经代理时才测** | 该源 `proxy_enabled` 为真、且 `proxy.host/port` 非空才测；否则界面标「未启用」 |

> `demo` 三条都不测：本地假数据，不出网（恒可用）。
> 「该站允许经代理」看的是后端 `sources.<key>.proxy_enabled` 字段 —— 该字段本轮**没有 UI 入口**
> （逐源代理勾选被整块拿掉），页面显示的是它的后果。

#### 2.5.2 测速目标登记（每个源登记一个固定字节数的小目标）

**纪律：绝不拿模型权重测速。** 每个源登记一个**已知体积 < 1 MiB** 的小目标，测速请求用 `Range` 取固定区间。

| 源 | 延迟目标（沿用 §2.1） | 吞吐目标（Range，≤ 256 KiB） | 备注 |
|---|---|---|---|
| huggingface | `GET /api/models?limit=1` | 同 host 上的小文件，Range 取前 256 KiB | 登记项必须 < 1 MiB |
| huggingface（镜像） | 同上，换镜像 host | 同上，换镜像 host | 仅当 `mirror` 非空才测 |
| modelscope | `GET /openapi/v1/models?PageSize=1` | 模型仓库里的 `README.md`，Range 取前 256 KiB | |
| civitai | `GET /api/v1/models?limit=1` | `civitai.com` 侧的小静态资源，Range 取前 256 KiB | |
| github | `GET /api.github.com/rate_limit` | `raw.githubusercontent.com` 上的小 README，Range 取前 256 KiB | 节点清单与模板都走 raw 域 |
| templates | `HEAD raw…/README.md` | 同上 | |
| comfyhub | `HEAD comfy.org/workflows/download` | 该页 Range 取前 256 KiB | |
| demo | 不测 | 不测 | 本地假数据 |

> **落地时必须逐一核验登记目标存在且体积 < 1 MiB**，否则换登记项；登记表随代码走，改了要重算。

#### 2.5.3 测量口径

| 项 | 取值 | 理由 |
|---|---|---|
| 延迟 | 建连到**首字节**（TTFB），毫秒 | 用户要的是「点下去多久开始动」，不是完整耗时 |
| 吞吐 | 固定字节数 ÷ 传输耗时，MB/s（1 MiB = 1.048576 MB） | 可比，与文件大小无关 |
| 取样 | 每条通路 1 次，失败最多重试 1 次 | 与 §2.2 的重试纪律一致 |
| 单通路预算 | ≤ 8 s | 测速比探针多一次传输，给宽一点 |
| 单站总预算 | ≤ 15 s（三条通路并发） | 与 §2.2 的单源上限一致 |
| 轻量 | 响应体读取 ≤ 64 KB（§2.2 的规矩）＋ Range 固定区间 | 不吃带宽、不污染缓存目录、不落盘 |

#### 2.5.4 速度读数的缓存

| 项 | 取值 |
|---|---|
| 缓存位置 | **与可达性结论同一份缓存**（同一键、同一 TTL），不另开一份 |
| TTL | 可达 15 min / 降级 10 min / 不可达 3 min（§2.4 不变） |
| 立即失效 | ① 改代理 host/port ② 改某源 `proxy_enabled` / `use_mirror` / `mirror` ③ 点「重新测试连通性」 |
| 落盘 | 不落盘（同 §2.4） |

> **一条硬规矩**：结论与速度必须同时失效、同时刷新。
> 不允许出现「结论是新的、速度是旧的」这种混搭 —— 策略是拿速度做决策的，混搭会选出错的通路。

> **⚠ 示意值声明**：本规格与原型页上的所有延迟、MB/s 数字**都是示意值**。
> 本轮**没有对任何站点发过真实的可达性探测请求，也没有发过真实的测速请求**；
> 页面上的数字是写死的样例，用来展示「结论 + 速度」怎么呈现、怎么比较。
> 真落地时必须用真实测速结果校准，阈值按实测分布重新定。

## 3. 源门控规则

### 3.1 四种结论与判定

| 结论 | 判定 | 提供入口 | 发请求 | 界面徽章 |
|---|---|---|---|---|
| `ok` 可用 | 当前生效通路成功 | 是 | 是 | 可用（绿） |
| `degraded` 降级 | 当前生效通路失败、备用通路成功 | 是（标注降级） | 是（走备用通路） | 已降级 · 走代理（橙） |
| `down` 不可用 | 所有探过的通路都失败 | **否** | **否** | 不可用（红） |
| `unknown` 未知 | 从未探测 / 刷新失败 | 是（**不门控**） | 是 | 未探测（灰） |

> **关键一条**：只有 `down` 才门控。`unknown` 不门控 ——
> 否则第一次打开应用、还没探过时，所有源都不出现，那不叫门控，那叫把产品藏起来。
>
> **第三轮追加：每一态都要带速度读数**（§2.5）——
> 可用 → 「最快的那条通路 ＋ 吞吐 ＋ 延迟」；降级 → 「降级到哪条通路 ＋ 它的速度」；
> 不可用 → 「三条都不通 ＋ 各条的失败原因」；未知 → 「还没探过」。
> 速度读数与结论同源、同缓存（§2.5.4）。

### 3.2 推荐做法（原型页 §3 方案 B）：**灰置 + 一行原因**，不是直接消失

| | 入口直接消失 | **灰置 + 一行原因（推荐）** |
|---|---|---|
| 发现页 | 筛选条里没有该源 | 该源 chip **灰置、点不动**，条下方一行说明原因 |
| 下载页 | 下拉里没有该源 | 下拉里保留该选项但 **禁用**，选项文案带原因 |
| 满足「不提供可选入口」 | 是 | **是**（灰置项不是可选入口：不响应点击、不发请求） |
| 代价 | 用户会以为「产品不支持这个源」；网络一换界面自己变了，用户无从察觉 | 界面上多一行说明；筛选条里留一个灰 chip |

> **设置页不套用这一套。** 「灰置 ＋ hover 提示」是给**发现页 / 下载页的筛选区**用的
> （入口藏起来、鼠标悬停才说原因）；**设置页要把状态与速度直接写出来** ——
> 逐条列出「哪条通路通不通、多快、为什么」，因为用户来这一页就是要看这个，不该再点一次才知道。

### 3.3 降级策略（自动收缩搜索范围）

1. 「全部」搜索只发往 `ok` / `degraded` 的源；`down` 的源**不发请求**（不浪费一轮超时）。
2. 若所有外网源都 `down`：自动切到 **demo** 源，并在页面顶部提示「当前网络无法访问模型源，先用离线演示数据」。
3. `degraded` 的源照常参与搜索，但结果行标出「经代理获取」。
4. **探针不自动改任何持久化配置**（不改 `proxy_enabled`、不改策略）。它只报告 + 给一个「改走代理」的按钮，
   那是用户的显式动作。

### 3.4 手动 override（逃生口）

| 项 | 规定 |
|---|---|
| 字段 | `settings.sources.<key>.always_enabled`（**新增**，默认 `false`） |
| 效果 | `true` 时该源永不被门控，即使探针判 `down` |
| 界面 | 源状态卡显示「已手动启用（忽略探针）」 |
| 位置 | **本轮页面上没有它的位置**（新结构里没有高级区，也没有逐源代理开关） |
| 降级影响 | 手动启用的源若确实连不上，错误信息照常返回（不静默吞掉） |
| **本轮页面位置** | **页面上没有它的入口**。新结构里每张站点卡只暴露凭据与镜像（hf/gh）＋ CivitAI 的完整目录开关，逐站代理开关被整块拿掉。该字段先留在后端（默认 `false`），要不要补回 UI **待拍板**（见 §9 第 6 条） |

### 3.5 界面措辞（三态可区分）

- 正常：不加任何额外说明。
- 降级：「直连不通，已改走代理 · 412 ms」。
- 不可用：「直连超时 · 代理可用 → 去设置」。
- 未知：「还没探过 · 探测一次」。

### 3.6 下载策略按探针实测速度自动选择（第三轮修订）

用户要求（第二轮）：「这个策略是根据探针的状态自动选择的，客户可以点击解锁后强制更改。」
用户追加（第三轮）：「**改成按探针实测速度选最快的可用通路**，不再是固定 mirror/direct/proxy。」

**策略的语义变了**：从「下载器怎么取址」变成「**选哪条网络通路**」。

#### 3.6.1 三个选项（sdk 不提供入口）

| 选项 | 对应 | 参与速度排名 | 说明 |
|---|---|---|---|
| **直连（direct）** | `direct` 通路 | ✅ | 官方地址直连 |
| **镜像（mirror）** | `mirror` 通路 | ✅ | 走该站配置的镜像 / 加速前缀（HF 的 hf-mirror、GH 的加速前缀） |
| **代理（proxy）** | `proxy` 通路 | ✅ | 官方地址，但强制经全局代理 |
| **sdk（官方 SDK）** | 独立的下载器 | ❌ 不参与 ＋ **不提供入口** | **已定：设置页不出现 sdk 入口（选 A）**，见下方说明 |

> **sdk 为什么不提供入口**（已核对代码；用户 2026-11-22 拍板 **选 A**）：
> 只有 `huggingface` 与 `modelscope` 真正实现了 `supports_sdk()`（`backend/app/sources/huggingface.py:98`、
> `backend/app/sources/modelscope.py:83`）；其余源继承 `backend/app/sources/base.py:51` 的 `False`。
> `backend/app/download/manager.py:209` 的分支是 `if task["strategy"] == "sdk" and adapter.supports_sdk()`，
> 所以 civitai / github / comfyhub 选 sdk **无效**，会落回普通下载（`_aria2_file`）。
> 而且 sdk 通路**不走普通下载器** —— 是 huggingface_hub / modelscope 自己的下载器，
> **没有分片、没有断点续传**，拿它跟另外三条通路比速度也不公平。
> **结论**：设置页**完全不提供 sdk 入口**，默认全走普通下载通路；
> **后端的 sdk 分支保留不动**，将来要用再说 —— 这一段只作为规格附注，**不是界面选项**。

> **语义变化要说明白**：旧口径里 `mirror` 是「镜像优先 ＋ 失败换站重试」的**兜底策略**，
> 新口径里 `mirror` 是「就走镜像这条通路」。两者不是一回事。
> 落地时要按新口径改 `download/manager.py` 的策略分支；旧口径是否保留为独立选项，见 §9。

#### 3.6.2 自动选择规则

**层级一 · 每站选通路**（**发现与下载两条通道的实际行为 —— 走的是同一条**）：

> **代理门槛（2026-11-22 用户定）**：代理的速度只有比直连或镜像**快 20% 以上**才默认走代理；
> 优势在 20% 以内（含「快一点点」）默认**不走代理**，走直连或镜像里更快的那个。
> 判定按**实测吞吐**比，**不按延迟**比。

判定式：

```
base    = max(direct_speed, mirror_speed)     /* 未测通 / 未配置的通路速度记 0，不参与竞争 */
走代理  ⟺  proxy_speed > 1.2 × base           /* base = 0 时只要代理测通就走代理 */
否则    →  走 base 对应的那条（direct 与 mirror 里更快的；两者都没测通时自然落到代理）
```

| 情况 | 该站选中的通路 |
|---|---|
| 有通路测通 | 按上面判定式选：先过 20% 代理门槛，再取吞吐最高的一条；吞吐相差 ≤ 0.1 MB/s 时取**延迟更低**的那条 |
| 直连与镜像都没测通、代理测通 | 走**代理**（base = 0，不受门槛限制） |
| 三条都不通 | **不可用** → 该源在发现页与下载页被门控，下载链路不向它发请求 |
| 未探测 | **不选**（也不门控），后台异步探完再定 |

**层级二 · 全局默认策略**（设置页「下载策略」卡展示的那一个）：

| 情况 | 选出 |
|---|---|
| 三条通路至少有一条测通 | 把各站实测吞吐**按通路汇总**（该通路可测的站求和），**同样过 20% 门槛**后选整体最快的一条 |
| 三条一条都测不通 | **「不可用」**，并说明会被门控 |
| 探针还没探完（多数站未探测） | 沿用上次保存的策略，不猜 |

> **页面上的这段说明不写死数字**：设置页「当前自动选择的算式」那段文字与策略卡结论**同源** ——
> 都由上面这条聚合算式从**同一份探针实测数据**算出来（同一个 `aggregate()` 结果），页面里不预置任何汇总数字。
> 探针数据一变（重新测试连通性），那段文字跟着变。

**层级三 · 发现与下载共用同一份结论**（2026-11-22 用户定）：

- 同一站的**发现（列表）与下载两条通道走同一条通路** —— 不是「下载走最快、发现另算」。
- 两条通道读的是**同一份探针缓存结论**（§2.4 的那份进程内缓存），不各自再探一次。
- 因此**卡片上显示的通路、详情里显示的通路、策略卡算出的结论必须一致**：
  站点卡显示该站实际会走的那条；策略卡的「默认走 X」是全局汇总值，
  直连被挡的站按自己的最快通路走（示例：CivitAI 走代理），卡片上写明原因。

#### 3.6.3 界面口径

| 项 | 规定 |
|---|---|
| 锁定态（默认） | 卡片上**只显示「自动」徽标 ＋ 一句结论**（例「默认走直连」）＋ 一个「解锁」按钮。**没有依据长句、没有速度列表** —— 挪到页面下方说明区与本节 §3.6.2 |
| 解锁 | 出现**策略下拉**（直连 / 镜像 / 代理）＋「恢复自动」；下拉选中即生效 |
| 手动选定后 | 结论一行显示「已指定 X」，小徽章由「自动」变「手动」；点「恢复自动」回到自动值。**手动指定不受 20% 门槛限制**（门槛只管自动判定） |
| 手动指定不可用时 | 回退到该站最快的可用通路，并在站点卡上标出「回退到 X」 |
| sdk | **不提供入口**（已定，选 A）：策略下拉只有 直连 / 镜像 / 代理 三项，页面上没有任何可点的 sdk 项；适用范围与代码依据见 §3.6.1 |
| 依据来源 | 与 §2.5.4 同一份缓存；策略与徽章读的是同一份状态 |

**自动值要不要写盘**（与 §3.3 第 4 条的关系）：

- 探针**不直接改写** `settings.json`；
- 自动选出的策略是**页面上的生效值**（随探针变化，未保存前不落盘）；
- 用户点「保存设置」或解锁后手动指定，才写回 `download.strategy`；
- 这样既满足「策略跟着探针实测速度自动走」，又守住「探针不偷改用户配置」这条老规矩。

## 8. 验收清单（定稿后落地时逐条可判定）

1. 一次探测请求返回全部 7 个源的结论；每源含通路、结论、延迟、时间戳、失败类别。
2. `POST /api/proxy/test` 的行为与返回结构**未变**（老调用不破）。
3. 可达结论缓存 15 分钟、不可达 3 分钟；改代理地址后该源缓存立即失效。
4. 命中过期缓存时先返回旧结论并标「结果已过期」，后台刷新不阻塞页面。
5. 手动连续点「重新探测」不会产生并发重复外网请求（10 秒冷却 + single-flight）。
6. 单轮探测整体不超过 15 秒，单请求响应体读取不超过 64 KB，不落盘、不进缓存目录。
7. `down` 的源在发现页不可点、在下载页被禁用，且**后端不再向它发请求**。
8. `unknown`（未探测 / 探测异常）时**不门控**，所有源照常可见可用。
9. `degraded` 的源仍可见可用，界面标注「已降级 · 走代理/镜像」。
10. 每条失败原因在界面上的措辞与 §2.3 表一致。
11. `always_enabled=true` 的源即使探针判 `down` 也不被门控。
12. 新装环境里 `sources.civitai.proxy_enabled` 为 `false`，`huggingface` / `github` 为 `true`。
13. 老配置里已保存的 `civitai.proxy_enabled=true` 不被自动改写；设置页显示「与推荐值有 1 处差异」。
14. 老 `settings.json` 缺 `always_enabled` 时加载不报错，取值为 `false`。
15. 设置页是**左右双栏**，左栏（宽）放 6 张站点卡、右栏（窄）放「本地代理配置」与「下载策略」两张卡；栏宽比 7:3（实测 868 px : 372 px）。
16. 6 张站点卡齐全：huggingface / modelscope / civitai / github / templates / comfyhub，**一张不少**；**demo 不在设置页出现**。
17. 每张站点卡内含：四态结论徽章与色条、**三条通路（直连 / 镜像 / 代理）各自的读数条格**（状态 ＋ 延迟 ＋ 吞吐）、卡脚一行结论。
17a. 站点卡是**紧凑卡**：单卡 ≤ 140 px（实测 133 px）、卡头 ≤ 40 px、读数条 ≤ 55 px；6 张卡 + 工具条 + 一句话说明在一屏（1000 px 视口）内能看全（实测左栏 976 px ≈ 933 px）。当前值读数**排在卡脚同一行**，不另起一行、不加高卡片。
17b. 完整读数（失败分类代码与人话）进「详情」展开，且「详情」可展开、可收起；读数条每格带 hover 气泡。
18. 「重新测试连通性」是**卡片外的一个全局按钮**，一轮重测全部 7 个站，不是每卡一个按钮。
19. 左栏的说明块**只有一句**：「下载、列表都会通过探针的结果缓存走最快的那条。」；缓存口径（可达 15 min / 降级 10 min / 不可达 3 min / 改代理地址立即作废 / 未探测不门控）在页面下方「状态数据流」区与规格 §2.4 / §2.5.4 里，不占左栏主视觉。
20. 站点卡的「编辑」按钮**只出现在** huggingface / modelscope / civitai / github 四张卡上；templates / comfyhub **没有编辑按钮**（demo 卡已删除）。
21. 编辑面板**只出现该站支持的字段**：hf＝Token+镜像、ms＝Token、civitai＝**Token+完整目录（18+）**、gh＝Token+镜像；不支持的字段**不出现**（不置灰、不只读）。
22. 点开编辑面板可展开、可收起；同时只开一张。
23. 下载策略卡默认**锁定**，展示自动选出的策略；点「解锁」后出现**下拉**，可选 **直连 / 镜像 / 代理 三项**（没有 sdk），解锁态在视觉上与锁定态明确区分，并能「恢复自动」。
24. 页面上**不存在**任何与模型下载目录有关的字样、输入框或选择按钮 —— 连说明文字也没有。
25. 页面上**不存在**任何内核参数（连接数 / 分片数 / RPC 端口 / 并发）字段，也不出现相关字样。
26. 站点卡里**不存在**逐源「下载时经全局代理」勾选。
27. 落地改产品侧时，`settings.component.ts` 里的「模型下载目录」与「aria2 内核与默认策略」两个 panel 被整块删除。
28. 每张站点卡列出**三条通路**（直连 / 镜像 / 代理）各自的状态、延迟、吞吐；不测的通路明确写「未配置 / 未启用 / 不适用」。
29. 四态每一态都带速度读数：可用/降级给出最快或降级通路的吞吐与延迟；不可用给出各条失败原因；未知写「还没探过」。
30. 下载策略锁定态显示三条通路的**实测速度**与**选中理由**；点「解锁」后可强制指定 直连 / 镜像 / 代理，并能「恢复自动」。
31. 设置页**不提供 sdk 入口**：策略下拉只有 直连 / 镜像 / 代理 三项；页面上**不存在任何可点/可选的 sdk 项**（按钮、下拉项、单选按钮都不得出现）。sdk 的适用范围与代码依据只写在规格里。
32. 三条通路都不通时，策略显示「不可用」并说明该源会被门控。
33. 设置页把状态与速度**直接写出来**，不套用发现页 / 下载页筛选区的「灰置 ＋ hover 提示」。
34. 测速请求是轻量的（Range 固定区间、≤ 256 KiB），**不拿模型权重测速**；响应体读取 ≤ 64 KB、不落盘。
35. 原型与规格里的速度数值标注为**示意值**；本轮未对任何站点发过真实可达性探测或测速请求。
36. 代理卡的测试结果条**只显示「成功」或「失败」**：不带错误原因、不带延迟毫秒、不带「直连」那一段；成功为绿、失败为红。
37. 下载策略卡**只有三样**：当前策略一行、一个「解锁」按钮、解锁后出现的策略下拉（直连 / 镜像 / 代理）＋「恢复自动」。
38. 策略卡里**不存在**速度列表、「依据」长句、各站选中通路、每个选项的小字解释、锁定说明长句、sdk 区块。
39. 策略依据（三条速度、为什么选它）在**页面下方说明区**与本规格里，不在卡上；sdk 的口径在说明区与本规格里各一两句。
40. CivitAI 的编辑弹层里**恰好两项**：Token ＋ 「完整目录（CivitAI Red）」复选框（标题与说明沿用产品侧文案），不多不少。
41. 四张有可编辑项的站点卡上都有**当前值读数**（示例「Token 未设置 · 完整目录 关」），位置一致（在卡脚那一行）；勾上 CivitAI 的完整目录开关，卡片读数从「关」变成「开」。
42. 下载策略卡在**自动态**只显示「自动」徽标 ＋ 一句结论（如「默认走直连」）；卡上**没有依据长句、没有速度列表**。
43. 代理只有在 <span class="mono">proxy_speed &gt; 1.2 × max(direct_speed, mirror_speed)</span> 时才默认走代理 —— 判定按**实测吞吐**比，**不按延迟**比；手动解锁后指定代理**不受该门槛限制**。
44. 同一站的**发现（列表）与下载**走**同一条通路**，读同一份探针缓存结论；卡片读数、详情里的通路、策略卡结论**三处一致**（示例：CivitAI 直连被挡 → 走代理，卡片与详情都写代理）。
45. 设置页说明区「当前自动选择的算式」里的数字与页面聚合结果**逐个对得上**（胜出通路汇总值、20% 门槛值、代理合计、各站实测之和），且**静态模板里不写死任何汇总数字**；重新测试连通性后，说明区的数字跟着探针数据一起变。
