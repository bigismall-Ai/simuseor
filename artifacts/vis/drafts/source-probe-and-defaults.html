VIS Draft · Source Probe & Source Gating

统一源探针 · 源可用性门控

这一页回答三件事：一次探测怎么覆盖所有对外源、探针结论长什么样、结论怎么作用到发现页与下载页。 配套的规格文档在 drafts/source-probe-and-defaults-spec.md。

页内所有延迟、耗时与时间点都是示意值，不是实测结果；灰色源是拿来说明「不可达」长什么样的示例。 本轮只出原型与规格：backend/ 与 web/ 未改一行，prototypes/ 生成管线与 SiMuseor-VIS.md 未改。

00结论速览

先给结论，再看形态。下面每一条都对应页内某一节。

探针覆盖范围 一次探测覆盖 7 个源；每个源探两条通路（直连 / 经代理），Hugging Face 另探镜像。 结论只回答「能不能连上」，不回答「要不要下载」。
门控 · 推荐 不可达源在发现页与下载页灰置 + 一行原因，不直接消失。 消失 = 用户以为产品没这个源；灰置 = 用户知道有、知道为什么、知道去哪修。
默认通路 Hugging Face 与 GitHub 默认走代理（墙内直连最易失败）； CivitAI 默认直连。每条默认旁边都写清「为什么是这个值」。
缓存与失效 可达结论缓存 15 分钟、不可达 3 分钟。命中过期缓存时先返回旧结论并后台刷新， 界面标「结果已过期」而不是假装没探过。
逃生口 每个源有「始终启用（忽略探针）」开关，放在高级区、默认关闭。 探针误判时源不会被锁死。
本轮边界 只出原型页与规格文档，落地代码等定稿后另开一轮。 并入 VIS 生成管线的方式写在规格 §8。

01源状态卡 · 定稿形态

字段各回答一个问题：源名与接口 = 这是谁；通路列 = 直连 / 代理 / 镜像各自的结果； 结论 = 当前生效通路能不能用；延迟 = 用的是哪条路径的数；时间 = 这个结论有多旧。

  • 改代理地址、改某源通路、改镜像前缀 → 立即作废该源缓存，不必等 TTL。

03门控怎么作用到下游

用户的要求是「探针探出来连不上的源，就不要在发现页或者下载里支持」。 「不提供可选入口」有两种做法，代价不同，这里并排摆出来。

Option A

入口直接消失

未采纳
128个模型 来自 2 个源
全部 Hugging Face ModelScope 来源筛选
代价：CivitAI 的入口整个不见了，用户会以为「这个产品不支持 CivitAI」， 而不是「现在这台机器连不上 CivitAI」。网络一换，界面自己变了，用户无从察觉。
好处：最干净，不给任何可能失败的点击。

Option B

灰置 + 一行原因

推荐
128个模型 来自 2 个可用源
全部 Hugging Face ModelScope CivitAI 来源筛选

CivitAI 当前不可达（直连超时），已停用该源的搜索与下载。 代理通路可用 → 去设置

好处：灰置的 chip 不是可选入口（点不动、不发请求），满足了「不提供该源的可选入口」； 同时把原因说清楚，并给一个能修的动作。源还在，只是现在到不了。
代价：界面上多了一行状态说明；筛选条里会留一个不可点的灰 chip。

04默认配置怎么写才不像随手定的

「HF 和 GH 默认走代理、CivitAI 默认直连」这件事，光给一个开关位，用户只会当成随手一勾。 写法上要给出依据，并且给出这默认值在什么条件下会失效。

启用代理

正例

开关 + 依据 + 例外

这样写
CivitAI直连

默认直连 —— CivitAI 直连多数可用，套代理反而慢。 何时该改：直连超时或被墙时，打开开关走代理即可。

Hugging Face经代理

默认走代理 —— 墙内直连最容易失败，且权重体积大，失败代价最高。 何时该改：你有稳定的镜像站或直连环境时，切回直连更快。

默认取值与依据

源默认通路为什么是这个值探针能改吗
Hugging Face 经代理 墙内直连最容易失败；权重体积大，失败一次代价高（重来一遍）。 否（探针只报告，不改配置）
GitHub 经代理 节点清单、官方模板、工作流都走 raw.githubusercontent.com，直连不稳且失败是「整个节点页空掉」。 否
CivitAI 直连 直连多数可用；套代理会多一跳、明显变慢。不可达时探针会提示「代理可用」，一键改。 否（给「改走代理」按钮，但那是用户的动作）
ModelScope 直连 魔搭本身境内可直连，默认不需要代理。 否
ComfyUI 官方模板 / ComfyHub 直连 免鉴权固定源；模板走 raw 域（已并入 GitHub 一起探）。 否
Demo 本地 本地假数据，不出网，不参与探测；所有外网源都不可用时的兜底。 —

一句话口径：默认走代理的两个源，是「失败代价最高」的那两个；默认直连的，是「直连本来就通」的那些。 默认不是猜的，是按失败代价排的。

05候选方案 · 探针放在哪

同样的探针结论，放的位置不同，设置页的信息密度和用户的动线也不同。

Option A

内嵌在设置页每张源卡里

备选
Hugging Face可达 · 312 ms
经 127.0.0.1:7890

直连 ✕ 超时 · 代理 ✓ · 3 分钟前 [重新探测]

  • 好处：配置与结论挨着，改完立刻看到结果；不需要跳转。
  • 代价：4 张源卡各挂一条探测带，设置页变长一倍；「改配置」和「看状态」两件事挤在一张卡里。
  • 代价：「重新探测全部」没有天然位置；批量重探要在每张卡上点 4 次。

Option B

独立「连接体检」面板 + 设置页放摘要与入口

推荐
连接体检1 个源不可用

7 个源 · 5 可用 · 1 不可用 · 1 未探测 · 上次 3 分钟前 [重新探测全部]

Hugging Face可达312 ms
CivitAI不可用直连超时
设置页里的摘要位

连接体检 · 5 可用 · 1 不可用（CivitAI）　[打开体检]

  • 好处：状态集中在一处，一眼看完、一键重探；设置页保持干净，「默认配置」不被诊断信息淹没。
  • 好处：体检面板可以是独立页面（甚至启动时的一次性检查），设置页只留一行摘要与入口。
  • 代价：想看某个源的明细要多点一次；改完代理后要记得回体检面板重探。
推荐 Option B。理由：设置页这一轮的主题是「减负」（§5 另一页）， 把 7 条诊断信息塞回 4 张源卡里，等于把刚减下去的复杂度换个地方再加回来。 体检面板让「状态」和「配置」各占一页各说一件事；设置页只留一行摘要 + 入口，不丢信息。
若将来要在设置页里放摘要位，摘要必须一行、带结论数字与入口，不展开明细。

06需要拍板的点

这一页已经把选项摆开了，下面四条是真正需要你拍板的（规格文档 §9 有完整清单）。

#决策点推荐另一选项的代价
1 不可达源是消失还是灰置？ 灰置 + 一行原因 消失更干净，但用户会以为产品不支持这个源，且网络一变界面自己变了
2 探针结果放设置页还是独立面板？ 独立「连接体检」面板 内嵌则设置页变长一倍，与「减负」目标相反
3 探针能不能自动改配置？ 不能，只给「改走代理」按钮 自动改 = 机器替用户改网络策略；误判时用户很难察觉已被改动
4 老用户的 CivitAI 代理开关要不要跟着改默认值？ 不自动改，设置页提示差异 自动改 = 偷偷改用户已保存的设置；不自动改 = 新老用户行为不一致
