数出来一共几套写法：搜索 3 套（即时 / 回车提交 / 防抖 300ms）、筛选 3 套控件（chip 行 / 右侧 rail 分面 / segmented 分段）、排序 2 套（自造菜单 1 处、原生 select 5 处）、空态 1 个组件但三态只分了两档（搜索无匹配 与 筛选后为空，在任何一页都没分开过）、「清除全部筛选」0 处（模型库只有分面级的「重置」）。外壳本身已经统一（ui-collection-bar = 状态行 + 筛选行，六页共用），所以要统一的不是布局，是壳里面这几样：写法、措辞、可见性。

定稿 · 一行筛选条 ＋「筛选」浮层搜索框 → 站点筛选 → 筛选按钮（带徽标）→ 排序 → 读数与清除全部
一行里放什么从左到右：搜索框 → 站点筛选（chip 行）→「筛选」按钮（漏斗图标 ＋ 已选条件徽标）→ 排序下拉 → 视图切换 → 行右端的结果读数与「清除全部筛选」。
其余类别筛选去哪全部收进「筛选」按钮点开的浮层（div 浮层，锚在按钮下方）—— 模型类型 / 任务、用途、格式、排序权重等不属于「站点」的维度。浮层里分组呈现：分组标题 ＋ 每组的选项 chip ＋ 每项计数；底部有「清除全部」与「完成」。
站点筛选为什么留在外面站点是最常用的一层（先定从哪个站找），留在外面一行可见；类别维度多且低频，收进浮层。两层是两件事 —— 站点决定「从哪儿找」，类别决定「找什么样的」。
筛选维度控件沿用已定：chip 行直陈，阈值 ≤2 组 / 每组 ≤6 项；超出收进浮层。
排序控件沿用已定：原生 select，选项「按 X」句式。

浮层可以真的点开：点「筛选」按钮 → 浮层出现；点「完成」/ 右上角 ✕ / 按 Esc / 点浮层外面 → 收起。徽标随浮层里的已选项实时变；「清除全部」把浮层里的已选项清空、徽标归零。灰置的站点项不可点，鼠标移上去出提示气泡 —— 原因不印在页面上，页面保持干净。

改了什么

① 上一轮说的是「双行分层：第二行铺完整类别筛选」，本轮取消第二行 —— 类别筛选从「铺在第二行」改为「收进「筛选」按钮点开的浮层」。省下的代价：筛选条不再比内容区高出一截，首屏能看到的卡片行数不变。

② 排序 / 视图 / 读数 / 清除全部筛选全部收进同一行：整条筛选条是一个工具条（缩范围 → 怎么看 → 看到了多少），不再拆成两行，也不再有第二个面板常驻。

③ 站点筛选留在外面可见（上一轮也定了），但与浮层里的类别筛选明确分层：前者选「从哪儿找」，后者选「找什么样的」。

④ 原 A 工具条式未采用：站点与类别两类筛选并排摊在一行，读者分不清哪枚 chip 管站、哪枚管类；站点候选还要带 hover 提示，一行更挤。

⑤ 原 C 侧栏分面未采用：六页里五页只有 1–2 个维度，常驻左栏换不回那点空间，却让列表整体右移、卡片网格从 4 列掉到 3 列；侧栏还得靠分组标题把站点和类别分开读，不如直接分层。

沿用上一轮已定的部分本轮不推翻：筛选维度控件（chip 行直陈）、阈值规则（≤2 组 / 每组 ≤6 项）、排序控件（原生 select，选项「按 X」句式）、结果计数写法（「42 / 128 个模型」）、空结果三态（集合为空 / 搜索无匹配 / 筛选后为空）。

三态必须分开 —— 今天六页里没有一页把「搜不到」和「筛没了」写成两句话。最接近的一句是「换个关键词或筛选条件试试；也可能是这个分组下还没有工作流」，两个原因挤在一句里，读者不知道自己该换词还是该松条件。统一口径：① 空集合给下一步（去发现 / 扫描入库）；② 搜索无匹配 → 清掉搜索词；③ 筛选后为空 → 松条件或全清。标题里要带上触发原因（关键词 / 条件数），不能只说「没找到」。
